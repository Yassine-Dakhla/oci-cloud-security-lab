WRITEUP 01
Topic
OCI + iptables
Problem
Port 80 filtered
Lesson
Firewall rule order

Why opening port 80 in OCI wasn't enough.

I had a host Nginx service listening on port 80. The OCI Security List allowed TCP/80. A local curl request worked. But an external Nmap scan still reported port 80 as filtered.

The wrong assumption

My first assumption was that the cloud firewall must still be blocking the request. That was incomplete because OCI was only one layer in the path.

What I checked

sudo ss -tulpn
sudo iptables -L INPUT -n --line-numbers
sudo iptables -S INPUT

The host had an explicit reject rule placed before the UFW-managed chains. So even though UFW allowed HTTP, packets never reached those rules.

The important lesson

Firewall tools are abstractions over ordered packet-filtering rules. A later allow rule cannot rescue traffic that an earlier rule has already rejected. Cloud security also means checking every control point in the request path, not just the provider console.

WRITEUP 02
Topic
Docker exposure
Decision
Localhost binding
Goal
Reduce direct attack surface

Why the container doesn't listen on the public interface.

It would have been easy to launch the container with -p 8080:80. Instead, the service is published as -p 127.0.0.1:8080:80.

The difference

A public bind makes Docker's published port reachable on the host's external interfaces if the surrounding firewall permits it. A localhost bind limits the published socket to the host itself.

The request path

Internet → Nginx :443 → 127.0.0.1:8080 → Docker

This gives the host reverse proxy a clear role as the intentional public web entry point, while the application remains behind it.

WRITEUP 03
Topic
SSH hardening
Risk
Remote lockout
Approach
Validate before reload

Hardening SSH without turning security into an outage.

The target configuration disabled password login and direct root login while preserving public-key authentication.

The safe workflow

sudo sshd -t
sudo systemctl reload ssh
# keep the current session open
# test a second SSH session before disconnecting

Running sshd -t before reload checks the configuration syntax. Keeping the original session open provides a recovery path while testing the new policy from a second connection.

Effective policy

PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes

The lesson was simple: hardening is not only about stronger settings. It is also about applying changes in a way that preserves operational access.
